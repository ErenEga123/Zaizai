# Standard Writing Workflow

## Stage 0 — Intake
Classify the request: brainstorm, research, outline, scene, chapter, revision, continuity audit, or canon maintenance. Capture requested length, POV, tense, style constraints, and scope only when supplied or necessary.

## Stage 1 — Context retrieval
Archivist reads global rules and the smallest relevant set of canon/state/manuscript records. Include adjacent chapters when continuity depends on them. Return source references and an explicit UNKNOWN list.

## Stage 2 — Preflight
Continuity Analyst checks chronology, location, character availability, physical condition, equipment, resources, relationships, active threads, and known/unknown information. Blocking contradictions are raised before drafting.

## Stage 3 — Planning
Planner produces scene purpose, POV, entry state, beats, conflict, turn, exit state, and causal links. The plan must not introduce unapproved facts as established truth.

## Stage 4 — Drafting
Writer follows the approved brief and plan. Preserve requested scope. Do not summarize when prose was requested. Do not resolve open threads without authorization.

## Stage 5 — Independent audits
Canon Auditor checks objective continuity. Knowledge Auditor checks information asymmetry. Developmental Editor checks motivation, pacing, voice, repetition, and readability.

## Stage 6 — Revision
Supervisor consolidates findings by severity. Writer revises blocking and major issues first, then editorial issues. Auditors recheck changed material.

## Stage 7 — Delivery
Return the complete requested text, followed by a concise audit report and unresolved questions only when relevant. Do not bury the prose under process notes.

## Stage 8 — State proposal
Create proposed deltas for events, character states, timeline, relationships, resources, and threads. Mark each item PROPOSED. No state or canon file is updated until the author approves.

## Stage 9 — Commit
After approval, update the relevant canonical/state records, inspect the diff, check for duplicate/conflicting facts, and commit with a descriptive message. Never claim a push or commit succeeded unless the tool confirms it.
